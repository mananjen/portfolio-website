# Domain docs

This repository uses a single-context layout:
- `GLOSSARY.md` at the repository root
- Architecture decision records in `docs/adr/`

Before exploring, read the glossary and ADRs relevant to the work.
If absent, proceed silently; domain-modeling creates them as needed.

Use glossary terms when naming domain concepts. Note missing concepts
for domain-modeling. Explicitly flag proposals that conflict with an
existing ADR, identifying the ADR and explaining the proposed change.
